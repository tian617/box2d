# Box2D：从数学物理到源码实现，再到优化

> 一套面向“想知道做了什么、怎样做、为什么这样做”的分章教材。
> 阅读顺序：**物理现象 → 数学模型 → 手算 → 朴素实现 → 当前源码 → 优化与代价**。
> 本目录独立于 `readmegrok/`，不修改原文，也不修改引擎源码。

## 1. 本书对应哪份代码

- 仓库：当前工作区的 Box2D。
- 源码基线：`dc67c40ba2ce1ad384b0c985dbc1b539cba9221b`。
- 提交日期：2026-09-03；提交标题：`pkgconfig support (#1102)`。
- [`CMakeLists.txt`](../CMakeLists.txt) 第 4–9 行声明版本 **3.2.0**。这里不据此声称它是某个官方发布标签。
- 文档核对日期：2026-09-10。
- 研究对象：`src/`、`include/box2d/`、`test/`，并参考 `readmegrok/` 的主题组织。

**后续源码变化后，行号可能移动。请优先按函数名定位，再核对分支。** 本书说明的是这一工作树，不把旧版本 Box2D 的实现直接套到当前代码上。

## 2. 和原文相比，重点补了什么

1. 不只给出公式：说明每个核心量的单位、方向、使用前提，以及公式怎么从前一步推出来。
2. 不只说“打一脚”：把冲量怎样同时改变平动与转动、怎样改变接触点速度算完。
3. 不只说“更稳定”：说明积分误差、约束耦合、位置修正注入速度以及 Relax 的作用。
4. 不把论文算法等同源码：明确区分**物理定律、数值模型、教学简化、当前实现**。
5. 先给单线程、标量、少量物体的正确方案，最后才解释动态树、缓存、睡眠、SIMD 与并行。
6. 修正原文中自由落体算例、有效质量名称、恢复 bias 符号、热启动步骤、CCD 范围等问题。
7. 用完整阶段表、算例、练习答案、源码索引和实验判据，帮助读者自查，而非只凭动画判断。

## 4. 不必一次读完：三条推荐路线

### 路线 A：数学基础一般，希望真正理解

按 `00 → 01 → 02a → 02 → 03 → 22 → 04 → 05 → 09 → 10 → 11 → 12` 阅读。

第一遍暂时跳过 GJK、CCD、复杂关节和所有并行实现。先能解释“一个圆落地为什么停住”，再追求完整引擎。

### 路线 B：已有物理基础，主要想读源码

按 `00 → 16 → 09 → 11 → 12 → 06 → 07 → 08 → 13～15 → 17～20` 阅读。

先看 `b2World_Step` 的主干，再精读 `b2SolveContacts_Overflow`。不要从 SIMD gather/scatter 或调度原子变量开始。

### 路线 C：希望自己写一个二维刚体引擎

以第 04 章的里程碑为主线，第 21 章的实验为验收。

先完成质点积分、圆碰撞、偏心冲量、盒子流形、累计投影与摩擦、堆叠、距离关节；之后再加动态树、睡眠与并行。**性能优化不能代替正确的几何和约束。**

## 6. 阅读与验证约定

- 公式使用 `\( … \)` 和 `\[ … \]`；需要 Markdown 阅读器支持数学渲染。即使未渲染，变量说明和计算步骤仍可对照阅读。
- 源码片段的围栏标明“起止行号与文件”；教学伪代码明确标注，不冒充当前公开 API。
- “教学算例”为了隔离一个因素可能关闭重力、摩擦、阻尼、睡眠或恢复；**不能把它的结果直接当作默认世界的逐位输出**。
- 算术复核与完整引擎测试是两回事。本次文档工作对关键算例做独立算术校验，不声称已执行全部 C 测试或测得性能提升。
- 没有“一读就能省略所有练习”的捷径。每章先算一个数字例，再找对应变量，比连续阅读公式更有效。
- 物理定律、碰撞几何、SAT、GJK 和冲量公式旁配有 SVG 示意图，放在 [`images/`](./images/)。先看图对符号，再代入该节数字例。
